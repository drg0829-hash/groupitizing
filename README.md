# Groupitizing experiment (jsPsych 8.3.0)

GitHub Pages에서 실행하는 브라우저 기반 점 배열 실험입니다. Java 언어가 아니라 **HTML + JavaScript**입니다. 기존 코드의 참가자 입력, 안내, 연습 4회, 블록 시작/휴식, Google Apps Script 전송 형식을 유지하고, 새로운 7조건 자극 생성과 4초 고정 제시를 적용했습니다.

## 파일

- `index.html` — 안내/연습/본 시행/키보드 응답/저장/화면 스타일
- `experiment-core.js` — 시행 스케줄, 3×3 격자, 공간 및 색상 배정, 유효성 검사
- `test_design.js` — Node.js로 420시행과 자극 생성 검사

## GitHub Pages 배포

1. 저장소 루트에 `index.html`과 `experiment-core.js`를 함께 업로드합니다.
2. GitHub 저장소 **Settings → Pages → Build and deployment → Deploy from a branch**를 설정합니다.
3. 배포된 Pages 주소에서 데스크톱 키보드로 실험을 진행합니다. jsPsych 스크립트를 CDN에서 불러오므로 인터넷 연결이 필요합니다.
4. 데이터는 `index.html`의 `SAVE_URL`에 설정된 기존 Google Apps Script 웹 앱으로 전송됩니다. 웹 앱 권한과 스프레드시트의 동작을 **테스트 계정으로 먼저 확인**해야 합니다. 서버 측 코드가 제공되지 않아 실제 Google Sheets 저장 성공 여부는 여기서 검증하지 않았습니다.

> **보안 주의:** 기존 파일의 Apps Script URL과 `SAVE_SECRET`을 그대로 이식했습니다. 공개 GitHub Pages에서는 브라우저에 내려가는 코드의 비밀키를 누구나 볼 수 있습니다. 해당 값만으로 데이터를 쓸 수 있는 서버라면, 연구 시작 전에 서버 측의 접근제어/요청 검증을 변경해야 합니다. 이름은 개인정보이므로 참가자 고지와 적절한 저장 권한을 확인하세요.

## 최종 조건과 횟수

| 코드 | 공간 | 색상 |
|---|---|---|
| R1 | 전체 직사각형 무작위 | 회색 |
| R2 | 전체 직사각형 무작위 | x좌표순 좌우 색 분리 |
| R3 | 전체 직사각형 무작위 | 무작위 혼합 |
| C1 | 좌우 2개 클러스터 | 회색 |
| C2 | 좌우 2개 클러스터 | 공간/색 분할 일치 |
| C3 | 좌우 2개 클러스터 | 공간/색 분할 크기 불일치 (점 1개) |
| C4 | 좌우 2개 클러스터 | 양쪽 클러스터에 두 색 혼합 |

- 총점: 8, 9, 10, 11, 12 (각 84회)
- 7조건 × 점 개수당 12회 = 420회
- 6블록 × 70회; 블록당 조건×총점 조합 2회
- 연습 4회는 별도이며 정답 피드백 1초 제공
- 모든 색 분할 A/B는 각 6회, 빨강/청록 크기 방향도 3회씩 반전; 즉, 3+5이면 빨강 3·청록 5와 빨강 5·청록 3을 같은 횟수 제시
- 공간 분할 A/B와 클러스터 좌우 크기 방향 균형화
- **격자 위치(좌/우 3×3 = 9개씩)는 회차별 독립 균등 난수로 추출하고 횟수 균형을 강제하지 않음**

공간/색 분할 정의:

| 총점 | A | B |
|---|---|---|
| 8 | 3+5 | 4+4 |
| 9 | 3+6 | 4+5 |
| 10 | 4+6 | 5+5 |
| 11 | 4+7 | 5+6 |
| 12 | 5+7 | 6+6 |

`C3`: 공간 A/색 B 또는 공간 B/색 A. 색상 1개만 반대 클러스터 색으로 변경합니다. `C4`는 두 클러스터 각각 빨강·청록을 모두 포함합니다.

## 자극 생성과 제시

기준 Canvas 960×540px, 흰 바탕, 점 반지름 7px, 점 중심 최소 거리 25px, 경계 여백 20px입니다. 클러스터 반지름은 우선 48~78px 사이에서 무작위 추출하며, 좌우 경계·화면 여백·클러스터 간 간격(원 둘레 간 최소 38px)을 만족하도록 제한합니다. **이 크기 값은 확정된 파일럿 결과가 아니라 구현용 초기 설정**입니다. 클러스터의 중심 셀은 3×3 중 무작위 선택하고, 셀을 재추첨하지 않은 채 그 안에서 유효한 중심을 찾습니다.

색상은 회색 `(128,128,128)`, 빨강 `(255,0,0)`, 청록 `(0,255,255)`으로 고정합니다. 참가자 HFP/DKL/모니터 색 보정은 하지 않습니다. 따라서 두 유채색의 휘도가 같지 않다는 제한이 있습니다.

점 제시는 **4초 고정**이며 그 동안 키 입력을 받습니다. 초기 응시는 1초. `3 4 3 Enter`처럼 숫자 키 **1~9를 누를 때마다 하나의 보고 그룹**으로 추가하고, 자동 합산합니다. 숫자 사이 Space는 무시하므로 눌러도 됩니다. Backspace로 마지막 그룹을 취소합니다. Enter 시 즉시 응답을 확정하고 입력을 잠그지만 **점 자극은 남은 시간에도 유지**합니다. 4초가 끝날 때 Enter가 없으면 `timed_out=true`, `response=null`로 기록하고 다음 시행으로 이동합니다. 종료 후 시행 간 간격은 300ms입니다.

> 보고 그룹의 단일 입력은 기존 코드와 동일하게 **1~9 범위**입니다. 참가자가 실제로 10~12개를 한 덩어리로 지각한 보고를 받고 싶다면, 숫자 구분자 기반의 다자리 입력 UI로 바꿔야 합니다. 이 입력 제한은 해석 시 유의해야 합니다.

## 데이터 형식

기존 Apps Script의 JSON POST 스키마를 유지합니다.

```json
{
  "secret": "(index.html의 설정값)",
  "filename": "groupitizing_...",
  "trial_columns": ["..."],
  "trial_rows": [["..."]],
  "dot_columns": ["..."],
  "dot_rows": [["..."]],
  "session_rows": [["field", "value"]]
}
```

- `trial_rows`: 입력 원문, 그룹별 입력 배열, RT(Enter까지), 첫 키 RT, 각 그룹 입력 시각, 오답/시간 초과, 조건, 면적, 클러스터 중심·격자·반지름 등
- `dot_rows`: 각 점의 좌표, 공간 클러스터, RGB 색상 라벨, 선택 격자
- `session_rows`: 참가자 이름/세션 ID/버전/기기 정보/진행 결과 요약
- 서버 저장은 최대 3번 시도합니다. 실패하면 CSV와 전체 JSON 백업을 내려받습니다(다운로드 허용 필요).

기존 서버가 `trial_columns`, `dot_columns`을 이용해 시트를 새로 만들거나 동적으로 기록한다면 새 컬럼이 적용됩니다. 기존 시트의 열 수나 구조가 고정돼 있다면 서버 코드를 수정해야 합니다.

## 개발 점검

```bash
node test_design.js
```

자극 생성과 조건 배정은 자동으로 검사했습니다. 화면 입력 이벤트도 브라우저 환경에서 모의 점검했습니다. CDN 접속과 실제 Apps Script 응답을 포함한 **종단 간 실험은 배포 후 별도로 확인해야** 합니다.
